## Overview

While continuing to develop my Unity and C# skills, I spent a week learning Godot 4 with GDQuest's *Your First 2D Game With Godot 4: START*. My goal was to get comfortable navigating a different engine, understand the structure of an existing 2D project, and make and test changes in a playable game.

This was a guided learning sprint, not a claim of mastery. I used the starter project to build familiarity with Godot's workflow and see how changes in the editor affected the running game.

## Learning the Godot Workflow

### Navigating the editor and project

I practised finding my way around Godot's editor and exploring the parts of the starter project relevant to the game. This helped me get comfortable moving between the editor, project files, and the running scene.

### Understanding scenes, nodes, resources, and scripts

I explored how scenes, nodes, resources, and scripts are organized in the project and how they contribute to the 2D game. Learning this structure helped me understand where game elements live and where to look when investigating a behaviour.

### Making changes and testing them

I worked through the edit-run-observe cycle: make a change, run the project, observe the result, and refine my understanding. The screenshots show both the project in the Godot editor and the game running.

## What I Practised

- Navigating Godot 4 and its editor workflow
- Exploring an existing 2D game's scenes, nodes, resources, and scripts
- Locating project elements related to a change
- Running the game and checking how edits affect the playable scene
- Applying existing game-development knowledge while learning a different engine

## Reflection

Coming from Unity, I could use familiar game-development concepts as a starting point while learning how Godot organizes its projects and workflow. The one-week sprint helped me become more comfortable exploring and modifying an existing Godot project.

My main takeaway was that structured learning works best when paired with hands-on experimentation. I treated tutorials as a way to understand the workflow, then used the editor and running game to check my understanding. This is a foundation for continued Godot learning, rather than a claim that I mastered the engine in a week.
