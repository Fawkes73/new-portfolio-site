## Project Overview

LaunchBox is a browser-playable Unity game made for the Brackeys Game Jam 2026. Eight people collaborated across different time zones, brainstorming ideas and building toward a shared submission deadline. My contribution focused on implementing the NPC system and exploring ways to organize its data.

## NPC Roaming with NavMesh

I implemented NPC roaming using Unity's NavMesh navigation system. Instead of manually controlling every movement step, the NPCs use navigable areas in the environment as the basis for movement.

- Integrated NPC movement with Unity NavMesh
- Configured and tested navigation through walkable areas
- Connected roaming behaviour to the NPC gameplay implementation
- Troubleshot navigation issues during development

## Proximity-Triggered Dialogue

I connected NPC proximity to a dialogue UI interaction. When the player approaches an NPC, the proximity condition triggers a dialogue popup.

**Interaction flow:** Player movement → NPC proximity detection → Dialogue trigger → UI popup

This work connected a condition in the game world to UI behaviour, making the NPC interaction part of the player's experience.

## Exploring Data Approaches

I experimented with JSON and Unity ScriptableObjects while investigating how to store and organize project data. This was exploration and testing—not a claim that I completed a production save/load system.

- **JSON:** Explored as a text-based serialization format that can be paired with file I/O and serialization logic for runtime data.
- **ScriptableObjects:** Explored as Unity assets for storing and sharing structured project data, such as configuration or dialogue content.

These approaches serve different purposes. ScriptableObjects are not a runtime save system by themselves, and JSON does not provide a complete data model or persistence workflow on its own. Comparing them helped me understand that the choice depends on what data needs to be stored and how the game uses it.

## Debugging and Learning

The implementation involved unfamiliar Unity workflows and errors that needed investigation. I used error messages, documentation, and tutorials to understand the issues, test possible solutions, and verify behaviour in the project.

This iterative process helped me break a larger problem into smaller parts: identify what was failing, investigate the relevant system, apply a targeted change, and test it before moving on.

## Collaboration Under a Game-Jam Deadline

The eight-person team worked across different time zones during an intensive day-and-night development schedule. I brainstormed ideas with the team and coordinated my NPC work with the shared project as the game evolved.

The jam taught me to balance implementation, troubleshooting, communication, and the time available for submission. My focus was the NPC system; the team worked together on the rest of the game and its final delivery.

## What This Project Demonstrates

- **NPC navigation:** Implementing roaming behaviour with Unity NavMesh
- **Gameplay-to-UI interaction:** Triggering dialogue UI through player proximity
- **Data exploration:** Comparing JSON and ScriptableObjects without overstating the result
- **Problem-solving:** Researching unfamiliar workflows and iteratively debugging issues
- **Team delivery:** Coordinating a focused technical contribution across an eight-person team and a shared deadline
